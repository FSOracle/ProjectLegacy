# 称号显示修复

版本：`1.1.1-rankfix`。

## 1. 加入和结算缺少自定义 Rank

自定义 rank 的底层权限值为 `NONE`，实际显示文字独立保存。部分游戏提示仍只读取内置 rank 的颜色或直接拼接游戏名，因此称号只出现在聊天和 Tab，没有出现在加入或结算提示中。

本次将下列公开提示接入统一的玩家显示名称：

| 模式 | 修复范围 |
|---|---|
| 起床战争 | 等待加入、退出，沿用统一名称的胜利者和击杀榜，聊天中的称号状态判断 |
| 空岛战争 | 加入、退出、胜利者、结算击杀榜、单人模式的获胜者提示 |
| Duel | 加入与获胜广播 |

显示名称包含 title、自定义或内置 rank，以及玩家名。空岛结算遇到已离线玩家时，会读取已保存的玩家资料；没有资料时使用原游戏名。

自定义称号仍然不授予 OP 或其他内置 rank 权限。正常设置的资料无需迁移，也不需要重新执行 `/rank`。内部权限值 `NONE` 不是显示失败，不要通过手工修改权限 rank 来修复称号。

游戏中原有的队伍颜色、击杀提示和队伍头顶标识继续使用各模式规则。

## 2. 右括号被截断

大厅头顶使用原版队伍前缀，最多 16 个 Java 字符，颜色代码计入长度。旧实现直接从右侧截断，可能恰好删除右括号。

新的缩短顺序：

1. 完整内容不超限时保持原样。
2. 超限时先缩短或省略额外 title，给 rank 留出空间。
3. rank 本身超限时缩短文字，保留左右括号及右括号的有效颜色。
4. 最后确保玩家名恢复为完整 rank 的主色。

不会切断颜色代码或 Unicode 代理对。聊天、Tab 和存档仍保留完整文字，只有受长度限制的大厅头顶会缩短。协议长度不足时无法完整展示所有前缀文字。

## 3. 更新与验收

正常停服，备份旧插件和玩家资料，替换 `plugins/Hypixel2020.jar`，完整重启后确认插件版本为 `1.1.1-rankfix`。不需要清空配置、地图或资料。

| 操作 | 预期结果 |
|---|---|
| 设置自定义 rank 后加入起床、空岛、Duel | 加入广播包含 title 和 rank |
| 完成各模式并查看结算 | 胜利者或结算榜单使用完整显示名称 |
| 空岛结算前有上榜玩家退出 | 已保存资料存在时仍保留该玩家的称号 |
| 设置长 title 和短 rank | 头顶优先缩短 title，rank 括号成对 |
| 设置长文字及多色括号 rank | 头顶缩短文字，右括号保留且颜色正确 |
| 查看聊天、Tab 和资料 | 完整文字及原配色不被头顶缩短逻辑改变 |
| 使用原版队伍模式 | 队伍颜色和可见性逻辑维持原规则 |

新增回归覆盖名称服务、游戏名称入口、可见 rank 与权限 rank 的区分，以及 1,920 组长称号、括号颜色和 Unicode 组合。全套构建还包含原有 Duel、Pit、好友、NCP 和最终产物检查。

本次构建通过，31 项 JUnit 测试及 14 项游戏名称合约检查通过。最终产物包含 22 个必须存在的类或资源；未被源码覆盖的 896 个 NCP 类保持不变。

当前 Windows 环境仍跳过 Duel 偏好存档成功提交后的重启验证，其他测试检查保存失败后的关闭行为。此限制与本次称号修复无关。尚未进行真实多客户端联机验收。
