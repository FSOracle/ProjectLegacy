# 2026-11-01 更改说明

本次更改包含管理员指令 `/rank` 和按世界过滤 Tab 玩家列表。

后续已增加括号自定义配色、相邻颜色继承及独立 `/title`。请以 [Rank 括号颜色与 Title 前缀](rank-title-guide.md) 为当前称号用法；下文部分限制和测试统计记录的是早期版本。

适用环境：本项目的 Spigot 1.8.8 服务端，使用 Minecraft Java 版 1.8.9 客户端验收。此次更新不要求玩家安装客户端模组。

## 1. 新增 `/rank` 管理指令

### 1.1 用途与权限

为指定在线玩家设置内置 rank 或自定义称号。支持 Minecraft 颜色名称，以及自定义称号中的 `&` 颜色代码。玩家名字采用称号中占比最高的颜色。

需要权限 `h2020.admin`。默认 OP 拥有此权限；控制台也可以执行。普通玩家不能执行或获得该指令的参数补全。

赋予 `ADMIN` rank 不会执行 `op`，也不会自动授予 `h2020.admin`。其他模块对 rank 的既有判断仍然适用，因此 rank 不应被当作完全独立于游戏行为的装饰。

### 1.2 指令格式

游戏聊天框：

```text
/rank <player> <rank或自定义称号> [color]
```

服务端或 MCSManager 控制台：

```text
rank <player> <rank或自定义称号> [color]
```

`<...>` 表示必填参数，`[...]` 表示可选参数。输入时不要带这些括号。

| 参数 | 必填 | 含义 | 示例与限制 |
|---|---|---|---|
| `player` | 是 | 目标玩家的游戏名 | `Steve`；必须在线，支持 Tab 补全 |
| `rank或自定义称号` | 是 | 内置 rank，或自定义文字 | `VIP`、`MVP+`、`Builder`、`建筑师`；支持空格 |
| `color` | 否 | 内置 rank 的覆盖颜色，或自定义称号的起始颜色 | `gold`、`dark_aqua` 或 `&c`；省略时内置 rank 使用默认配色，自定义称号从灰色开始 |

rank 和颜色名称不区分大小写。多个单词的颜色名称使用下划线，例如 `dark_aqua`。

#### 自定义称号和名字颜色

不能匹配内置 rank 的文字会作为自定义称号，自动显示为 `[称号] 玩家名`。

```text
/rank Steve 建筑师 gold
/rank Steve Event Staff aqua
/rank Steve &aAB&bC
```

自定义称号支持 `&0` 到 `&f` 分段颜色，不能包含方括号、控制字符、直接输入的 `§`、粗体或其他格式代码。

玩家名字颜色按最终称号中每种颜色覆盖的可见字符数计算，包含系统添加的方括号，不计空白和颜色代码。并列时取最先出现的颜色。例如 `&aAB&bC` 中绿色和青色各占两个字符，名字使用绿色。默认 `[YOUTUBE]` 有七个白色字母和两个红色括号，所以名字使用白色。

为保证聊天、大厅头顶和 Tab 一致，自定义称号最多 11 个可见字符，而且包含颜色代码、方括号、空格和名字颜色切换的完整前缀不得超过 16 个 Java 字符。多色称号允许的文字会更短；超限会拒绝，不会静默截断。以上两个限制同时适用。

末尾能识别为颜色的参数会被当成颜色，例如 `Event Staff gold` 的称号是 `Event Staff`。如需让称号以颜色名称结尾，可追加真正的颜色参数，例如 `/rank Steve Team Gold white`。

自定义称号使用 `NONE` 作为底层 rank，不继承旧 `ADMIN` 等 rank 的行为，也不会授予 OP 或管理权限。重新设置任何内置 rank，或执行旧 `/h2020 rank`，会清除自定义称号；`/rank Steve NONE` 可以清除称号。

### 1.3 Rank 参数表

| 参数标准写法 | 也接受 | 显示称号 | 省略颜色时的默认配色 |
|---|---|---|---|
| `NONE` | `none` | 无称号 | 名字为灰色 |
| `VIP` | `vip` | `[VIP]` | 绿色 |
| `VIP_PLUS` | `VIP+` | `[VIP+]` | 绿色，加号为金色 |
| `MVP` | `mvp` | `[MVP]` | 青色 |
| `MVP_PLUS` | `MVP+` | `[MVP+]` | 青色，加号为红色 |
| `MVP_PLUS_PLUS` | `MVP++` | `[MVP++]` | 金色，加号为红色 |
| `YOUTUBE` | `youtube` | `[YOUTUBE]` | 红色括号，白色称号文字，名字为白色 |
| `ADMIN` | `admin` | `[ADMIN]` | 红色 |

`NONE` 表示移除称号。如果同时指定颜色，例如 `/rank Steve NONE aqua`，玩家没有称号，但名字使用指定颜色。

### 1.4 Minecraft 颜色参数表

下表两种参数形式均可使用。颜色代码需要保留 `&`，例如输入 `&c`，不能只输入 `c`。

| 颜色参数 | 颜色代码 | 颜色 |
|---|---|---|
| `black` | `&0` | 黑色 |
| `dark_blue` | `&1` | 深蓝色 |
| `dark_green` | `&2` | 深绿色 |
| `dark_aqua` | `&3` | 深青色 |
| `dark_red` | `&4` | 深红色 |
| `dark_purple` | `&5` | 深紫色 |
| `gold` | `&6` | 金色 |
| `gray` | `&7` | 灰色 |
| `dark_gray` | `&8` | 深灰色 |
| `blue` | `&9` | 蓝色 |
| `green` | `&a` | 绿色 |
| `aqua` | `&b` | 青色 |
| `red` | `&c` | 红色 |
| `light_purple` | `&d` | 浅紫色 |
| `yellow` | `&e` | 黄色 |
| `white` | `&f` | 白色 |

此参数只接受颜色。`bold`、`italic`、`reset`、`&l` 等格式参数会被拒绝。要恢复默认配色，重新执行指令并省略颜色参数。

### 1.5 用法示例

| 操作目标 | 游戏内指令 | 结果 |
|---|---|---|
| 赋予 VIP，使用默认配色 | `/rank Steve VIP` | 绿色 `[VIP] Steve` |
| 赋予 VIP，整段改成金色 | `/rank Steve VIP gold` | 金色 `[VIP] Steve` |
| 使用 rank 简写和颜色代码 | `/rank Steve MVP+ &b` | 整段青色 `[MVP+] Steve` |
| 赋予 ADMIN，指定红色 | `/rank Steve ADMIN red` | 红色 `[ADMIN] Steve` |
| 恢复 MVP+ 默认配色 | `/rank Steve MVP+` | 青色称号和名字，红色加号 |
| 移除称号并恢复灰色名字 | `/rank Steve NONE` | 无称号，灰色名字 |
| 移除称号但保留指定名字颜色 | `/rank Steve NONE aqua` | 无称号，青色名字 |
| 设置中文自定义称号 | `/rank Steve 建筑师 gold` | 金色 `[建筑师] Steve` |
| 设置带空格的称号 | `/rank Steve Event Staff aqua` | 青色 `[Event Staff] Steve` |
| 设置多色称号 | `/rank Steve &aAB&bC` | 绿色 `[AB`、青色 `C]`，名字为绿色 |

Tab 补全顺序：在线玩家名、rank 标准写法、颜色名称。补全 rank 时返回 `MVP_PLUS` 等标准写法，手动输入 `MVP+` 也可以。

### 1.6 显示范围和保存行为

- 聊天中的 rank 前缀和名字使用新配色；聊天正文颜色不由此参数控制。
- 大厅头顶称号、Tab 名字、资料菜单和 rank 侧边栏文本使用新配色。
- 大厅中的目标玩家会触发称号和侧边栏刷新。
- 对局中头顶和 Tab 名字还可能受游戏队伍显示规则控制；本次没有替换队伍配色逻辑。返回大厅后按玩家资料显示。
- 真人资料写入运行目录下的 `plugins/Hypixel2020/profiles.yml`。本地脚本运行时，其完整相对路径为 `run/plugins/Hypixel2020/profiles.yml`。
- 自定义配色保存为 `rank-color`；恢复默认配色时移除此字段。
- 自定义称号保存为 `custom-rank-title`，颜色代码以 Minecraft 内部格式存储。真人资料重进和正常重启后保留。
- 旧资料没有 `rank-color` 时继续采用原来的默认配色。
- Bot 仍遵循原有临时资料规则，不承诺退出或重启后保留手动设置。

### 1.7 与旧指令的区别

| 指令 | 可选颜色的作用 | 兼容行为 |
|---|---|---|
| `/rank <player> <rank或自定义称号> [color]` | 设置内置 rank 或自定义称号，允许分段颜色 | 省略颜色时内置 rank 恢复默认配色，自定义称号从灰色开始 |
| `/h2020 rank <player> <rank> [plusColor]` | 沿用旧的加号颜色逻辑，主要用于 MVP+/MVP++ | 执行后清除整段自定义颜色，使用旧配色规则 |

例如：

```text
/rank Steve MVP+ gold
```

会显示整段金色。随后执行：

```text
/h2020 rank Steve MVP_PLUS BLUE
```

会恢复青色的 MVP+ 称号和名字，并使用蓝色加号。

### 1.8 常见错误

| 现象或提示 | 原因 | 处理 |
|---|---|---|
| `Usage: /rank ...` | 缺少玩家或称号 | 输入在线玩家名和称号，可选追加颜色 |
| `Player must be online: ...` | 找不到指定在线玩家 | 确认玩家已进入本服并核对名字 |
| `Invalid title. ...` | 称号为空、超长、格式不合法或完整前缀超过 16 字符 | 缩短称号或减少分段颜色，使用颜色表中的代码 |
| `Invalid color. ...` | 颜色名称无效，或输入了粗体等格式 | 使用颜色表中的名称或 `&` 颜色代码 |
| 被拒绝执行或提示没有权限 | 没有 `h2020.admin` 权限 | 由服主确认权限，或通过服务端控制台执行 |
| 对局内名字仍显示队伍颜色 | 游戏模式正在管理队伍标识 | 回大厅检查资料配色，单独验收队伍显示 |

## 2. 修复 Tab 显示全服玩家的问题

### 2.1 修复前后

修复前：Tab 中可能同时出现大厅、其他游戏世界和其他对局地图的在线玩家。

修复后：为每个查看者按世界过滤在线玩家和 Bot。同世界玩家按现有可见性规则显示，其他世界玩家不进入该查看者的 Tab 名单。

此功能随插件启用，不需要执行指令，也没有新增配置参数。

| 场景 | 预期行为 |
|---|---|
| 玩家在主大厅 | 看到该世界内按现有规则可见的玩家和 Bot |
| 玩家进入空岛或起床对局 | 清理原世界名单，显示目标世界名单 |
| 玩家进入另一张独立世界地图 | 不再显示原地图的玩家 |
| 其他玩家或 Bot 进入本世界 | 更新本世界相关查看者的名单 |
| 玩家退出 | 正常移除该玩家的名单项 |
| 大厅隐藏玩家功能开启 | 保留原来的隐藏规则 |
| 对局切换旁观状态 | 保留原来的旁观者可见性规则 |
| NPC 加载皮肤 | 保留原有添加后移除的短暂名单流程 |

### 2.2 生效边界

- 隔离依据是 Minecraft 世界，不是地图名称、房间编号或玩家坐标。
- 两个房间如果共用一个世界，不能靠本次修复互相隔离 Tab。
- 同一地图模板生成的不同世界副本，按各自世界隔离。
- 切换世界后在后续调度任务中刷新名单，不承诺客户端在切换瞬间已经完成全部更新。
- 数据包过滤保留移除操作，避免留下旧名单项。
- 过滤时复制需要修改的广播包，避免影响其他世界的查看者。
- 此更改只处理玩家名单，不修改玩家实体可见性，不增加新的消失或隐身权限。

## 3. 构建、更新和回退

### 3.1 构建

在项目根目录执行：

```powershell
.\gradlew.bat build --console=plain
```

构建要求 Java 17 或以上，运行服务端沿用 Java 8。构建产物为：

```text
build/libs/Hypixel2020.jar
```

构建成功不等于联机验收通过。

### 3.2 更新到测试服或线上服

1. 记录当前插件版本及运行目录，通知玩家维护。
2. 等待或结束当前对局，正常停服并确认进程已退出。
3. 备份旧插件和 `plugins/Hypixel2020/` 数据目录。
4. 将新 `Hypixel2020.jar` 替换到服务端 `plugins/` 目录，不保留另一个会重复加载的同名插件副本。
5. 完整启动服务器，查看控制台是否有插件启用或数据包处理异常。
6. 按下节检查 rank 和跨世界 Tab。

MCSManager 用户应在对应实例中停服、更换文件和启动。确认选择的是目标实例，不要把插件上传到其他实例或插件数据目录。

本次没有要求修改 `config.yml`。使用完整重启加载新指令及网络处理逻辑，不使用 `/reload` 代替更新。

本地使用 `start-server.bat` 时，脚本会重新构建并复制插件到 `run/plugins/`；不要同时启动两次脚本。

### 3.3 回退

1. 正常停服。
2. 恢复备份的旧插件；需要恢复数据时，使用与备份日期匹配的资料副本。
3. 启动并检查玩家资料及 Tab 行为。

旧代码不会显示新字段提供的整段配色。若旧版重新保存玩家资料，可能丢弃 `rank-color`，因此更新前应保留数据备份。
