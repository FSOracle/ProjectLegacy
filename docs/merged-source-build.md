# 完整源码合并与构建说明

本次以用户提供的 `src.zip` 为完整源码基底，合入之前的 rank、title、括号颜色和按世界显示 Tab 的修改。插件版本为 `1.1.0-merged`，可在控制台或游戏内查询插件版本以确认更新结果。

## 1. 保留的功能

| 功能 | 合并结果 |
|---|---|
| 起床战争、空岛战争 | 保留完整源码、注册和入口 |
| Duel | 保留 Classic、Boxing、NoDebuff、Bridge |
| The Pit | 保留世界、等级、奖励、存档、Bot 管理和 AI |
| 好友 | 保留好友关系、邀请、过期处理、存档与菜单 |
| 组队 | 保留组队、队伍聊天和组队排队 |
| Watchdog / NCP | 保留完整源码中的桥接、策略和配置 |
| `/rank` | 保留自定义称号、独立括号颜色、相邻颜色继承和名字主色 |
| `/title` | 保留 rank 前的独立文字、颜色及格式 |
| Tab | 继续只显示当前世界内按既有规则可见的玩家及 Bot |
| 大厅入口 | 保留完整源码中的 Duel、Pit 和社交入口 |

称号用法见 [Rank 括号颜色与 Title 前缀](rank-title-guide.md)。

## 2. 源码与依赖

游戏和插件源码位于 `src/main/java/`，直接参与构建。此次没有使用反编译源码，也没有用旧版插件覆盖完整模块。

压缩包附带的独立 NCP JAR 与原构建要求不匹配，因此从包内已编译插件提取了实际使用的 NCP 依赖。其 908 个类与单独找回的插件中的 NCP 类逐字节相同。固定依赖和校验说明位于 [vendor/README.md](../vendor/README.md)。

测试目录：

| 目录 | 用途 |
|---|---|
| `src/test/java/` | 真实 Bukkit API 上的 JUnit 测试，包括 rank、title、权限和存档格式 |
| `src/contractTest/java/` | 原完整源码的 NCP、好友、Duel 和 Pit 合约检查 |

NCP 合约检查使用的最小 Bukkit/NCP 桩只存在于合约测试目录，不进入普通测试类路径，也不会打包到服务端插件。

## 3. 构建

在项目目录执行：

```powershell
.\gradlew.bat build --console=plain
```

要求 Java 17 或以上用于构建。运行 Spigot 1.8.8 继续使用 Java 8。

固定 NCP 依赖已随仓库提供，无需额外指定本机路径。依赖缺失或校验不符时，构建会停止。

构建包含：

1. 全部插件源码编译。
2. rank/title JUnit 测试。
3. Duel、Pit、好友和 NCP 合约检查。
4. 最终 JAR 的模块、依赖和测试桩隔离检查。

生成文件：

```text
build/libs/Hypixel2020.jar
```

`verifyPluginJar` 检查 Duel、Pit、好友、组队、起床、空岛、rank、title 和 Tab 类均存在；还检查嵌入的 NCP 类、必要资源以及没有混入测试类。

本次验证结果：

- 干净构建 `clean build` 成功，完整源码参与编译。
- 27 项 JUnit 测试通过，包括跨世界 Tab、称号格式、权限和模块注册检查。
- Duel 完成 132 项已执行断言；Windows 上的偏好重启检查明确跳过，见下节。
- Pit 地图、等级和文件存档合约完成 31 项断言。
- 扩展 Pit 地图、好友存档、邀请过期、关系清理及 NCP 桥接合约通过。
- 最终产物包含 21 个必须存在的类或资源；896 个未由源码覆盖的 NCP 类与固定依赖逐字节一致，测试类及 API 桩未进入插件。

这些检查未模拟真实服务端完整启动，也不代替双客户端对局验收；Pit SQLite 数据库迁移和线上文件状态仍需在测试实例中验证。

## 4. 当前平台限制

原完整源码的 Duel 偏好文件要求原子替换后同步父目录。当前 Windows 文件系统拒绝此目录同步操作。

生产代码仍保持原来的处理方式：提交结果不确定时停止 Bot 匹配并拒绝后续修改。本次没有忽略生产存档异常。

Windows 下的测试验证该失败行为，并明确跳过成功保存后的偏好重启检查。Linux 上不会跳过这部分检查。部署前应在目标 Linux 文件系统运行同一构建，确认 Duel 偏好的完整持久化检查通过。

Pit 世界所有权代码也使用 Unix 文件属性，不能把 Windows 构建成功视为 Windows 开服兼容性证明。

## 5. 更新前后

1. 备份线上旧插件及完整 `plugins/Hypixel2020/` 数据目录，包含 Pit 数据和状态文件。
2. 正常停服，确认实例进程退出。
3. 替换 `plugins/Hypixel2020.jar`，不删除现有地图、配置和玩家资料。
4. 完整启动，确认版本为 `1.1.0-merged`。
5. 检查控制台的 `friend`、`party`、`pit`、`duels` 等模块启用记录，排查任何启用失败。
6. 验收大厅到各模式的入口、称号显示、跨世界 Tab 和正常退出重进。

不要为排除 Pit 错误直接删除 `pit-run.state`、所有权记录或存档。这些文件用于阻止不确定状态下继续覆盖数据，应先保留日志和备份后定位原因。

本次构建没有连接或更新线上 MCSM，也没有完成真实多客户端联机验收。
